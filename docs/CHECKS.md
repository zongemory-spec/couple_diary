# 本地验证与真实服务验收

## 本地

Node24：`npm ci --ignore-scripts`、`npm test`。Python：`python tools/generate_setup.py`、`python tools/build.py`。测试直接运行当前 `database/install.sql`，使用 PGlite（嵌入式 PostgreSQL）和合成 Auth/Storage 表；邮件网络、Auth HTTP 使用测试替身，不向真人发送。

覆盖邮箱校验、受邀邮箱匹配、邀请失效/撤销、接受幂等、最多两人、两对情侣隔离、跨房间照片/附件拒绝、信件收发/已读、作者权限、零元订单和发货、心愿归档、日期范围、并发修订、提交幂等、邮件偏好/租约/重试等。

## 真服务：维护者上线前完成

没有真实配置时不能声称完成以下验收。使用独立测试项目和测试邮箱，不把密钥、真实内容传到 GitHub。

1. 部署 install.sql、前端、Auth 自定义 SMTP 和邮件 worker。检查两个 Storage 桶 private，Confirm email 开启，跳转地址正确。
2. 用邮箱 A 注册，收确认信，确认后登录。创建房间，预填双方资料，邀请 B。验证复制链接和邀请邮件均可打开。
3. B 未验证时不能接受；用错误邮箱 C 打开链接应被拒绝。B 验证后登录，即使换浏览器也能发现自己的待接受邀请；确认资料后两人进入同屋。
4. C、D 创建第二间屋。同名记录、订单、照片、文档与信件只在各自两人内可见；手工粘贴另一间屋的 Storage 引用应被拒绝。
5. A 写信给 B，B 查看后 A 看到已读；邮箱提醒不含正文。切换账号、退出后不显示上一账号内容。
6. 小铺新增商品、0元下单、B 回复/发货；记录心情、照片回忆、心愿兑现；双方修改见面日期并上传/下载 PDF，确认倒计时和归档。
7. 检查每种事件邮件对应当前另一半，关闭接收提醒后停止普通事件邮件；撤销邀请后旧链接不可接受。
8. 两端同时编辑，旧版本应提示冲突而非覆盖。模拟断网和重复点击，记录与订单不重复。
9. 完成忘记密码和确认邮件重发，确认链接回到正式域名。检查移动端表单可滚动，照片授权过期后可重签。
10. 检查定时任务、发送配额与失败记录；服务商 accepted/sent 仅代表接收，实际收件箱另外确认。

本地预览：`python -m http.server 4173 --bind 127.0.0.1 --directory site`。未配置后台时会提示维护者配置，这是预期行为。
